# Exposition Park Parking Website

Static parking-information website for Exposition Park, Los Angeles. The site is built with Vite, Tailwind CSS, and Alpine.js and can be deployed to any static hosting provider.

## Contents of the handoff

The complete site source consists of:

- `index.html` — page markup, content, metadata, navigation, parking information, FAQ, and accessibility controls.
- `src/main.js` — Alpine.js components, interactive cards/modals, FAQ behavior, accessibility settings, image preloading, and scroll reveals.
- `src/style.css` — Tailwind CSS entry point and custom styles.
- `vite.config.ts` — Vite and Tailwind plugin configuration.
- `public/` — logos, icons, maps, parking diagrams, photographs, and other static assets. Files in this directory are copied to the root of the production build.
- `package.json` and `bun.lock` — scripts and pinned dependency resolution data.
- `DESIGN.md` — design-system and implementation notes.
- `WCAG-AA-handoff.md` — accessibility handoff notes and checklist.

`dist/` is generated output. It is not required in source control because it is excluded by `.gitignore`; regenerate it before delivery or deployment.

## Technology and dependencies

Runtime dependencies bundled into the site:

- Alpine.js `3.15.x` for lightweight interactivity and state.
- `@alpinejs/collapse` `3.15.x` for FAQ and expandable-content transitions.
- Tailwind CSS `4.1.x` for utility classes.

Build dependencies:

- Vite via the `rolldown-vite` package alias, version `7.2.5`.
- `@tailwindcss/vite` `4.1.x` for Tailwind integration with Vite.

The project does not contain a backend, API, database, server-side rendering, or required environment variables. All parking content is currently authored in `index.html` and `src/main.js`.

## Local development

Recommended tooling:

- Bun 1.x or a current Node.js/npm installation.

Using Bun:

```bash
bun install
bun run dev
```

Open the local URL printed by Vite, normally `http://localhost:5173/exposition-park/`.

Using npm instead:

```bash
npm install
npm run dev
```

Create a production build and test the generated files locally:

```bash
bun run build
bun run preview
```

The build output is written to `dist/`. The preview server is useful for checking asset paths and the deployed base path before publishing.

## Deployment

### Static hosts or a custom domain

For a root-domain deployment such as `https://example.com/`, update `vite.config.ts` before building:

```ts
base: '/'
```

Then run:

```bash
bun run build
```

Upload the contents of `dist/` to the host's public web directory. Do not upload only `src/`; the browser should receive the built files from `dist/`.

If the host uses a subdirectory other than `/exposition-park/`, set `base` to that exact path, including leading and trailing slashes, and rebuild.

### ZIP handoff

For a source handoff, include the project files listed above and exclude generated or machine-specific files such as `node_modules/`, `.git/`, `.DS_Store`, and local editor configuration. A practical source ZIP can be created with:

```bash
zip -r exposition-park-site-source.zip \
  index.html package.json bun.lock vite.config.ts \
  src public DESIGN.md WCAG-AA-handoff.md README.md \
  -x '*/.DS_Store'
```

For a host-ready ZIP, build first and archive `dist/`:

```bash
bun run build
cd dist && zip -r ../exposition-park-site-dist.zip . -x '*/.DS_Store'
```

## External resources and deployment considerations

- `index.html` loads the Source Sans 3 font from Google Fonts. The deployed site therefore makes requests to `fonts.googleapis.com` and `fonts.gstatic.com`. If an offline or self-contained package is required, download and self-host the font and update the stylesheet references.
- The page contains outbound links to Exposition Park, California government, Google Maps, Instagram, TikTok, and other external sites. Those links are not bundled into the ZIP and remain dependent on the external services being available.
- Assets are referenced from the Vite base URL in JavaScript. Keep the configured `base` value aligned with the hosting path.
- Browser APIs used include `IntersectionObserver`, `localStorage`, `window.scrollTo`, and `new Image()`. Current evergreen browsers support these features; older browsers may need a compatibility strategy.
- Accessibility settings persist in the visitor's browser via `localStorage`. They are not stored on a server.
- There is a legacy Elementor/jQuery integration at the end of `src/main.js`. The standalone Vite page does not declare jQuery or Elementor as dependencies. If the standalone deployment console reports `jQuery is not defined`, remove or guard that integration; if the page is embedded in an Elementor environment, ensure that host loads jQuery and the relevant Elementor popup event.
- Parking rates, event rules, addresses, and external map links are content managed in the source. Confirm them with the site owner before each production release.

## Content and maintenance locations

- Main page content and static sections: `index.html`.
- Directions, bus parking, ADA parking, and FAQ data: `src/main.js`.
- Colors, typography, responsive behavior, animation, and accessibility styles: `src/style.css`.
- Images and icons: `public/`.
- Design rationale and naming conventions: `DESIGN.md`.
- Accessibility review guidance: `WCAG-AA-handoff.md`.

## Pre-deployment checklist

1. Run `bun install` and `bun run build` without errors.
2. Run `bun run preview` and verify navigation, responsive menus, modals, FAQ accordions, map links, image loading, and accessibility settings.
3. Check the browser console for missing assets and the jQuery/Elementor integration warning described above.
4. Verify the site at the final hosting path; in particular, confirm that CSS, JavaScript, favicon, and images do not return 404 responses.
5. Test keyboard navigation, skip link behavior, focus states, contrast mode, text-size controls, and reduced-motion expectations against `WCAG-AA-handoff.md`.
6. Recheck parking rates, event guidance, ADA counts, hours, contact information, and third-party links.
7. Archive either the source ZIP or the built `dist/` ZIP, depending on the recipient's deployment workflow.
